## 2. 조원용 모듈 소개 (담당 모듈 고르기)

> 생물학 지식이 없어도 이해할 수 있게 풀어 썼습니다. 각 모듈의 **하는 일 → 만드는 과정 → 쓰이는 곳 → 화면 기능 → 난이도**를 보고 담당할 모듈을 골라 주세요.

### 2-1. 먼저 알아두면 좋은 용어
| 용어 | 쉬운 설명 |
|---|---|
| **H&E 사진** | 몸에서 떼어낸 조직을 아주 얇게 썰어 분홍색(E)과 보라색(H) 물감으로 물들인 현미경 사진. 병원에서 암을 진단할 때 가장 기본으로 찍습니다 |
| **WSI (Whole Slide Image)** | 유리 슬라이드 한 장 전체를 고해상도로 스캔한 사진. 한 장이 수만 × 수만 픽셀이라 작은 조각(**패치**)으로 잘라서 씁니다 |
| **생검** | 수술 전에 바늘로 종양 조직을 조금 떼어내는 검사. 이걸로 암인지 확인합니다 |
| **림프절** | 겨드랑이 등에 있는 콩알만 한 면역 기관. 암세포가 몸의 다른 곳으로 퍼질 때 가장 먼저 도착하는 "정거장" 같은 곳입니다 |
| **전이 / 재발** | 전이: 암세포가 처음 생긴 곳을 벗어나 다른 곳으로 퍼지는 것 / 재발: 치료가 끝난 뒤 암이 다시 생기는 것 |
| **바이오마커 (ER, PR, HER2, Ki-67)** | 암세포가 가진 "특징 표시". 어떤 약이 잘 들을지 알려줍니다. ER·PR이 있으면 호르몬 약, HER2가 많으면 HER2 표적 약을 씁니다. Ki-67은 암세포가 얼마나 빨리 늘어나는지 보여줍니다 |
| **IHC 검사** | 특정 바이오마커만 갈색으로 물들이는 특수 염색 검사. 정확하지만 마커마다 따로 해야 해서 시간과 돈이 듭니다 |
| **HER2 IHC 단계 (0 / 1+ / 2+ / 3+)** | HER2 단백질이 세포막에 얼마나 많이 물드는지를 4단계로 매긴 점수. 3+는 양성, 2+는 애매해서 유전자 검사(ISH)를 추가로 해서 양성·음성을 정합니다 |
| **Oncotype DX** | 암 조직의 유전자 21개를 분석해 "재발 위험 점수(0–100)"를 내는 검사. 이 점수로 항암치료를 할지 정합니다. 매우 비쌉니다 |
| **MIL (Multiple Instance Learning)** | 사진 조각이 수천 개일 때 조각마다 정답이 없어도 "환자 하나의 정답"만으로 학습하는 방법. 어떤 조각이 중요했는지 **히트맵**으로 보여줄 수 있습니다 |

### 2-2. 슬라이드 전처리 파이프라인 (`wsi_pipeline`)이란?
**H&E 슬라이드 사진을 AI가 학습할 수 있는 숫자 데이터로 바꾸는 전처리 과정**입니다. 모듈마다 예측 대상(재발, 림프절, 바이오마커, 유사 환자)은 다르지만 이 앞단 과정은 같습니다. **조원마다 이 파이프라인을 각자 독립적으로 만들어** 자기 모듈에 씁니다.

> 비유: 네 명이 각자 요리(모듈)를 하는데, **재료 손질도 각자 자기 요리에 맞춰 직접 하는 것**과 같습니다.

| 단계 | 하는 일 | 쉬운 설명 | 도구 예시 |
|---|---|---|---|
| ① 슬라이드 읽기 | `.svs`, `.tiff` 등 WSI 파일 열기 | 사진이 너무 커서 전용 라이브러리로 필요한 부분만 꺼내 읽습니다 | OpenSlide |
| ② 조직 영역 찾기 | 흰 배경, 먼지, 펜 자국을 빼고 조직만 남김 | 슬라이드 절반 이상이 빈 유리라서 버려 계산량을 줄입니다 | 색 임계값(Otsu) |
| ③ 패치 자르기 | 조직을 256 × 256 픽셀 조각으로 바둑판처럼 자름 | 슬라이드 한 장에서 수천 개가 나옵니다 | — |
| ④ 색 보정 | 병원·스캐너마다 다른 색감을 맞춤 | AI가 색 차이에 속지 않게 합니다 | Macenko 정규화 |
| ⑤ 특징 추출 | 사전학습 AI(encoder)가 패치마다 숫자 묶음(벡터)을 만듦 | 사진 조각을 **요약 숫자**로 바꿉니다. **가장 오래 걸리는 단계** (GPU 필요) | ImageNet ResNet50 |
| ⑥ 저장 | 슬라이드마다 "패치 벡터 + 패치 위치"를 파일 하나로 저장 | 원본 사진 없이도 학습할 수 있고 용량도 훨씬 작습니다 | `.h5` 파일 |

```
[wsi_pipeline — 조원마다 각자 구현]
WSI → ① 읽기 → ② 조직 찾기 → ③ 패치 → ④ 색 보정 → ⑤ 특징 추출 → ⑥ .h5 저장

[각자 만든 .h5로 모듈 개발]
  A: BCNB (+TCGA 외부 검증) → 모듈 2: MIL → 림프절 전이
  B: BCNB (+TCGA 외부 검증) → 모듈 3: MIL → ER/PR/HER2/Ki-67
  C: TCGA                   → 모듈 1: MIL → 재발 점수
  D: TCGA 또는 BCNB (택 1)  → 모듈 4-B: 슬라이드 벡터 + 임상 → 유사 환자 검색
```
- **①–⑥ 단계 구성은 모든 모듈이 같지만, 코드와 feature는 조원마다 각자 만듭니다.**
- 모듈 2(A)와 모듈 3(B)은 둘 다 BCNB를 쓰지만 feature는 각자 자기 파이프라인으로 뽑습니다.
- 주의: ⑤가 GPU로 수 시간에서 며칠 걸립니다. 네 명이 각자 추출하므로 **GPU 사용 순서를 미리 정해 두세요.**

### 2-3. 모듈 1. 재발 위험 예측 (Oncotype DX 점수 예측)
**한 줄 요약:** 비싼 유전자 검사 대신 H&E 사진만 보고 "재발 위험 점수"를 맞혀 봅니다.

**쉽게 말하면:** 유전자 검사로 받던 성적표를 조직 사진만 보고 미리 짐작하는 AI입니다. 실제로 암세포의 생김새(모양, 크기, 배열)와 유전자 점수 사이에는 관련이 있습니다.

**개발 과정**
1. TCGA에서 호르몬 수용체 양성(HR+) · HER2 음성 환자의 H&E 사진과 유전자 데이터를 받습니다.
2. 유전자 데이터에 Oncotype 21-gene 공식을 적용해 환자마다 **"정답 점수(유사 RS)"**를 계산합니다. 공개 데이터에 실제 Oncotype 점수가 없어서 직접 계산합니다.
3. 직접 만든 `wsi_pipeline`으로 사진을 feature로 바꿉니다.
4. MIL 모델이 점수를 예측하도록 학습시킵니다.
5. 예측 점수가 실제 재발(TCGA-CDR)과 잘 맞는지 확인합니다.

**쓰이는 곳:** 비싼 유전자 검사가 꼭 필요한 환자만 골라내는 **사전 선별**, 유전자 검사가 어려운 병원·국가에서의 대략적 위험도 확인

**화면 기능:** 예측 점수(0–100), 저위험 / 중간 / 고위험 표시, 점수에 영향을 준 조직 부위 히트맵

**난이도:** ★★★★☆ — 딥러닝(PyTorch), 대용량 이미지 처리, 생존분석(통계)

### 2-4. 모듈 2. 수술 전 림프절 전이 예측
**한 줄 요약:** 수술 전에 찍은 생검 사진만 보고 "겨드랑이 림프절로 암이 퍼졌을 가능성"을 예측합니다.

**쉽게 말하면:** 림프절은 사진에 아예 안 찍혀 있습니다. 그래도 종양의 생김새를 보면 "퍼지기 쉬운 성격의 암인지" 어느 정도 짐작할 수 있습니다. 결과는 개수가 아니라 **0개 / 1–2개 / 3개 이상** 세 구간으로 냅니다. 이 구간에 따라 수술 범위가 달라지기 때문입니다.

**개발 과정**
1. BCNB 데이터(환자 1,058명의 생검 사진 + 수술 후 실제 림프절 결과)를 받습니다.
2. 직접 만든 `wsi_pipeline`으로 종양 부분의 특징 벡터를 뽑습니다.
3. MIL 모델로 "전이 있음 / 없음"과 "3구간"을 예측하게 학습시킵니다.
4. 나이, 종양 크기 같은 진료 기록 정보를 함께 넣어 성능을 높입니다.
5. 기존 논문 모델(AUC 0.816)과 비교하고, 다른 데이터(TCGA)에서도 잘 되는지 확인합니다.

**쓰이는 곳:** 초음파에서는 "괜찮다"고 나왔지만 AI가 위험하다고 본 환자에게 **추가 검사 권고**, 수술 전 겨드랑이 수술 범위를 계획할 때 참고 자료

**화면 기능:** 전이 확률(%), 3구간 결과, AI가 주목한 조직 부위 히트맵, "추가 검사 권고" 알림

**난이도:** ★★★☆☆ — 공개 베이스라인 코드가 있어서 시작하기 좋습니다. 딥러닝 기본기가 필요합니다.

### 2-5. 모듈 3. 바이오마커 예측 + 기존 검사와 비교 (ER, PR, HER2, Ki-67)
**한 줄 요약:** 특수 염색(IHC) 없이 기본 H&E 사진만으로 바이오마커 결과를 예측하고, 실제 IHC 결과와 일치하는지 평가합니다.

**쉽게 말하면:** 원래는 마커마다 특수 염색을 따로 해야 합니다. AI가 기본 사진만 보고 "이 암은 ER 양성일 것 같다"고 먼저 알려주고, 실제 검사 결과와 다르면 "다시 확인해 보세요"라고 표시합니다.

**개발 과정**
1. BCNB의 **병리의 판독 결과**(ER·PR 양성/음성, HER2 상태와 IHC 단계, Ki-67 %)를 정답으로 씁니다.
2. 직접 만든 `wsi_pipeline`으로 BCNB feature를 뽑고, 마커마다 예측 모델을 만듭니다.
3. 예측값과 실제 검사값의 **일치도**를 통계 지표(κ, AUC 등)로 평가합니다.
4. ER·PR은 TCGA로 다른 기관 데이터에서도 맞는지 확인합니다.

**쓰이는 곳:** 병원 병리과의 **검사 결과 재확인(QC)**, 특수 염색 장비가 부족한 지역의 1차 분류, 의대생·전공의 **판독 연습용 교육 도구**

**화면 기능:** 마커별 예측 결과, 실제 검사 결과와 나란히 비교, **일치 / 경계 / 불일치 배지**, 불일치 케이스 모아보기

**난이도:** ★★★☆☆ — 파이프라인을 만든 뒤에는 마커마다 출력층만 바꾸면 됩니다.

### 2-6. 모듈 4-B. 멀티모달 유사 환자 검색
**한 줄 요약:** H&E 사진과 임상 정보를 함께 보고 **"이 환자와 가장 비슷한 과거 환자들"**을 찾아, 그 환자들이 어떤 치료를 받고 어떤 경과를 보였는지 보여줍니다.

**쉽게 말하면:** 의사는 어려운 환자를 만나면 "예전에 비슷한 환자는 어땠지?"를 떠올립니다. 이 모듈은 그 기억을 데이터로 대신합니다. 사진의 생김새와 나이·종양 크기·바이오마커가 비슷한 환자를 찾아 **"비슷한 환자 5명 중 3명은 이 치료를 받았고, 1명이 재발했다"** 같은 정보를 보여줍니다. AI가 정답을 정하는 게 아니라 **근거가 되는 실제 사례를 보여주는** 방식입니다.

**두 파트 중 하나를 골라 진행합니다 (택 1)**

4-B는 치료 과정의 어느 시점에 쓰느냐에 따라 두 파트로 나뉩니다. 두 파트는 답하는 질문이 다르고(수술을 어떻게 계획할까 / 수술 뒤 어떤 치료를 할까), 검색 DB와 학습 기준도 달라 모델 하나로 합칠 수 없습니다. 6주 안에 둘 다 하면 DB 구축·학습·평가를 두 번씩 해야 하므로 **1주차 첫 회의에서 하나를 골라** 끝까지 만들고, 고르지 않은 파트는 "향후 과제"로 남깁니다.

| 항목 | 파트 1. 회의용 유사 사례 | 파트 2. 수술 후 치료 참고 |
|---|---|---|
| 쓰는 시점 | 수술 전, 다학제 회의(치료 계획) | 수술 후 병리 → 보조 항암 결정 → 보조 요법 기간 |
| 답하는 질문 | "이 생검과 비슷한 환자들은 수술해 보니 림프절이 어땠나?" | "비슷한 환자들은 어떤 보조요법을 받았고, 경과는 어땠나?" |
| 돕는 결정 | 겨드랑이 수술 범위, 선행요법 여부 | 보조 항암 추가 여부, 보조 요법 상담 |
| 질문 슬라이드 | 생검 H&E | 수술 절제 H&E |
| 검색 DB | BCNB 1,058명 | TCGA-BRCA 300–500명부터 (최대 1,062명) |
| 보여주는 결과 | 림프절 결과(N0 / 1–2개 / 3개 이상), 수술 방법, 바이오마커 | 받은 치료, 재발 여부, 생존 기간·상태 |
| 없는 정보 | 치료·재발·생존 | 생검 단계 정보 |
| 선행항암 환자 | 쓸 수 있음 (생검은 항암 전) | 쓰지 않음 (치료 전 절제 조직 기준) |
| 연결 모듈 | 모듈 2 (위험 확률 옆에 실제 사례), 모듈 3 | 모듈 1 (위험군과 이웃 재발 비율), mini 처방 모듈 (처방 후보와 실제 치료 비교) |
| GitHub 공개 | 코드만 (BCNB 약관상 DB·벡터 공개 불가, 로컬 시연) | 코드 + DB + 환자 벡터 + 썸네일 |
| 주의 | 모듈 2와 하는 일이 겹쳐 보일 수 있음. "확률이 아니라 실제 사례"라는 차이를 분명히 해야 함 | 재발 이벤트가 적고, 치료 기록이 2000년대 미국 기준 |

아래 개발 과정과 7장의 설계는 **파트 2(TCGA) 기준**입니다. 파트 1을 고르면 TCGA를 BCNB로 바꾸고, 7장의 "파트 1을 고르면 바뀌는 점"을 따릅니다.

**개발 과정 (파트 2 기준)**
1. TCGA 임상 정보와 슬라이드 목록으로 **과거 환자 DB**를 만듭니다. 환자마다 바이오마커, 병기, 받은 치료, 재발·생존 경과를 정리합니다.
2. 직접 만든 `wsi_pipeline`으로 TCGA 슬라이드의 **슬라이드 벡터**를 뽑습니다.
3. 슬라이드 벡터와 임상 정보를 합쳐 **환자 벡터**로 바꾸는 딥러닝 모델을 학습시킵니다. "같은 아형·같은 경과인 환자는 가깝게, 다른 환자는 멀게" 배우도록 합니다(metric learning).
4. 모든 환자 벡터를 **벡터 검색 엔진(FAISS)**에 넣고, 새 환자가 오면 가장 가까운 k명을 찾습니다.
5. "사진만 / 임상만 / 둘 다" 세 방식으로 검색 품질을 비교해 **멀티모달이 더 나은지** 숫자로 보여줍니다.

**쓰이는 곳:** 파트 1은 수술 전 다학제 회의의 **수술 계획 참고 사례**, 파트 2는 수술 후 **보조요법 결정 참고 사례**와 환자 상담. 두 파트 모두 전공의 교육용 사례 검색으로도 쓸 수 있습니다.

**화면 기능:** 비슷한 환자 카드 5장(슬라이드 썸네일·히트맵, 바이오마커, "어디가 비슷한지" 표시) + 파트 1은 이웃 환자의 림프절 결과 분포, 파트 2는 받은 치료·재발 여부·생존 기간과 이웃 환자의 재발 비율 요약

**난이도:** ★★★☆☆ — 딥러닝(PyTorch), 대용량 이미지 처리, 벡터 검색, 데이터 정리. 슬라이드 벡터도 **직접 만든 파이프라인으로** 뽑습니다.

## 4. 모듈 1 — H&E → Oncotype DX 점수 예측 → 재발 예측

**데이터**
- **TCGA-BRCA:** H&E 진단 슬라이드, RNA-seq, 임상 정보. HR+/HER2− 환자만 사용하고, 처음에는 **300–500장으로 범위를 줄입니다.**
- **TCGA-CDR:** 표준화된 재발 endpoint(DFI, PFI).
- **유사 RS:** 공개 데이터에 실제 Oncotype 점수가 없어서, RNA-seq에 공개된 21-gene 공식을 적용해 직접 계산합니다.

**설계**
```
TCGA H&E → wsi_pipeline → ABMIL → ① 유사 RS 회귀 (0–100)
                                  ② 고위험 분류 (RS > 25)
                                  → ③ Cox 모델로 재발(DFI) 예측
```
- 평가: RS 상관계수(Pearson, Spearman), 고위험 분류 AUC, 재발 C-index.
- 분할: 환자 단위로 나누고, TCGA 수집 기관(TSS 코드)이 학습과 검증에 겹치지 않게 합니다.

**기존 모델**
- **Orpheus** (Boehm et al., *Nat Commun* 2025): H&E + 병리 리포트 멀티모달 transformer. RS ≤ 25 환자에서 원격 재발 예측 td-AUC 0.75로 RS 자체(0.49)보다 높았습니다.
- **Deep-BCR-Auto**: attention MIL, TCGA AUROC 0.827.
- **AnchorMIL** (2025): 회귀 + 분류 동시 학습, TCGA AUC 0.89.
- Prov-GigaPath fine-tuning (Cohen et al., medRxiv 2025).
- 2026 체계적 문헌고찰: 연구 11편이 있지만 무작위 임상시험 데이터로 검증된 것은 없습니다.

**한계:** 유사 RS는 진짜 RS가 아닙니다. TCGA는 재발 이벤트 수가 적어서 C-index 결과가 흔들릴 수 있습니다.

**실현성:** ★★★★☆

## 5. 모듈 2 — 생검 H&E → 수술 전 림프절 전이 예측

**범위**
- 원발 종양 **생검** 슬라이드만 보고 수술 후 병리 결과(pN)를 미리 예측합니다. 임상적으로는 초음파 등 영상 기반 cN 판정을 **보조**합니다.
- 정확한 림프절 **개수**는 예측하지 않고 **구간**(N0 / 1–2개 / 3개 이상, ACOSOG Z0011 기준)으로 분류합니다.
- 림프절 슬라이드에서 전이를 찾는 pN 판독 보조(CAMELYON 계열)는 이미 AUC 0.95 이상이고 상용 제품도 있어서 다루지 않습니다.

**데이터**
- **BCNB:** 조기 유방암 환자 1,058명의 core-needle biopsy WSI (환자당 1장), 종양 영역 일부 주석(JSON 다각형), 임상 정보 14열(`patient-clinical-data.xlsx`). 공식 분할은 학습 : 검증 : 테스트 = 6 : 2 : 2.
  - `ALN status`: **N0 655명 / N+(1-2) 210명 / N+(>2) 193명** → 3구간 정답. N+는 403명(38%)
  - `Number of lymph node metastases`: 0–9개 이상의 실제 개수 (구간을 직접 만들 때 확인용)
  - `Surgical`: 겨드랑이 림프절 곽청술 974명 / 감시림프절 생검 84명
  - 임상변수 후보: `Age(years)`, `Tumour Size(cm)`, `Tumour Type`, `Histological grading`(132명 결측), ER, PR, HER2, Ki67
- **TCGA-BRCA:** 수술 절제 WSI, pathologic N, 전이 림프절 수(`number_of_lymphnodes_positive_by_he`) → **외부 검증**. 생검이 아니라 절제 슬라이드라는 차이를 결과 해석 때 명시합니다.

**설계**
```
생검 H&E WSI ─ 조직 분할 ─ 종양 영역 ─ 20x 패치 ─ encoder ─ ABMIL ─ 슬라이드 벡터 ─┐
임상변수 (나이, 종양 크기, ER/PR/HER2, Ki-67, 조직형) ─ MLP ─────────────────────┴─ fusion
   → ① P(N+)   ② 3구간 (N0 / 1–2개 / 3개 이상)
```
- 확률을 그대로 보여주므로 calibration(temperature scaling)을 하고, 임계값은 민감도·NPV를 우선해 정합니다.
- 평가: AUC, 민감도·특이도, NPV, calibration curve, decision curve.
- 비교 실험: ① 임상변수만 쓴 로지스틱 회귀 → ② DL-CNB 재현 → ③ 우리 모델 → ④ 우리 모델 + 임상.

**기존 모델**
- **DL-CNB** (Xu et al., *Front Oncol* 2021, BCNB 원저자): VGG16_BN feature → attention MIL. 독립 테스트 AUC 0.816, 임상변수 결합 시 0.831. 코드 공개 ([BALNMP](https://www.github.com/bupt-ai-cz/BALNMP)) → **베이스라인으로 사용**.
- 상용 제품은 확인되지 않았습니다.
- **차별점:** 외부 검증(TCGA), encoder 비교, calibration·NPV 같은 임상 활용 지표, 임상변수 기준선과의 비교.

**실현성:** ★★★★☆

## 6. 모듈 3 — H&E → ER / PR / HER2 / Ki-67 예측 + 기존 검사와의 일치도 평가

### 6-1. 실제 데이터 확인 결과
**BCNB** (`BCNB/BCNB/patient-clinical-data.xlsx`, 1,058명, 결측 없음)
| 열 | 값 | 분포 |
|---|---|---|
| `ER` | Positive / Negative | 831 / 227 |
| `PR` | Positive / Negative | 790 / 268 |
| `HER2` | Positive / Negative | 277 / 781 |
| `HER2 Expression` | 0 / 1+ / 2+ / 3+ | 127 / 242 / 483 / 206 |
| `Ki67` | **양성 세포 비율 (0.01–0.90 소수)** 1,003명 + 범위 문자열 55명 (예: `30-40%`, `＞50%`, `＜5%`) | 중앙값 0.30 |

- **HER2 2+ 483명 중 71명이 양성**, 412명이 음성입니다 (ISH 결과로 갈린 것으로 보임). 0·1+는 모두 음성, 3+는 모두 양성입니다.
- **Ki-67은 실제 % 값이 있습니다.** 범위 문자열 55명은 20% 기준으로 변환합니다 (규칙은 6-2 참고).

**TCGA-BRCA** (`team_project_mini/data/tcga_brca/merged/tcga_brca_merged.csv`, 1,098명)
- `gdc_er_status_by_ihc`: Positive 808 / Negative 238 / 평가 안 함 49
- `gdc_pr_status_by_ihc`: Positive 699 / Negative 344 / 평가 안 함 50
- ER·PR의 % 구간과 강도 점수 열도 있지만 절반 이상이 `[Not Available]`이고, Allred · H-score는 자유 텍스트로 일부만 적혀 있습니다. → **ER·PR 양성/음성 외부 검증에만** 씁니다.
- HER2와 Ki-67은 **BCNB만 사용**합니다. TCGA의 HER2 IHC 점수(`gdc_her2_ihc_score`)는 약 620명에게 있지만 기관마다 판정 방법이 달라 섞지 않습니다. Ki-67은 TCGA에 없습니다.

### 6-2. 마커별 목표 (확정)
| 마커 | 예측 목표 | 정답 | 외부 검증 |
|---|---|---|---|
| **ER** | 양성 / 음성 | BCNB `ER` | TCGA `gdc_er_status_by_ihc` |
| **PR** | 양성 / 음성 | BCNB `PR` | TCGA `gdc_pr_status_by_ihc` |
| **HER2** | ① 양성 / 음성 ② IHC 4단계 (0 / 1+ / 2+ / 3+) | BCNB `HER2`, `HER2 Expression` | — (BCNB만) |
| **Ki-67** | ① **낮음(< 20%) / 높음(≥ 20%)** 이진 분류 ② 보조로 % 회귀 | BCNB `Ki67` | — (BCNB만) |
| (부가) 분자 아형 | 위 4개 예측을 조합해 Luminal A / B / HER2(+) / 삼중음성 | BCNB `Molecular subtype` | — |

- **Ki-67 20% 기준 분포:** 낮음 **341명** (숫자 329 + 문자열 12) / 높음 **709명** (숫자 674 + 문자열 35) / 판단 불가 8명 (`15-20%` 7명, `10-20%` 1명 → 경계에 걸쳐 제외). 분석 대상 1,050명.
  - **정확히 20%인 환자가 158명**이라 경계 정의가 결과를 크게 바꿉니다. "20% 이상 = 높음"으로 고정합니다(St. Gallen 2013과 같은 기준).
  - BCNB 원 논문에는 분자 아형을 나눈 Ki-67 기준이 공개돼 있지 않습니다. 데이터상 Luminal A/B 경계는 **15%와 18% 사이**이고, 15%에서는 A 78명과 B 10명이 섞여 있습니다.
  - 값이 10%, 15%, 20%, 30%처럼 반올림된 숫자에 몰려 있습니다(병리의 눈대중 판독). 그래서 % 회귀는 보조 지표로만 씁니다.
  - 범위 문자열 변환: `＜5%`, `＜10%`, `＜3%`, `＜1%` → 낮음 / `20-30%`, `30-40%`, `＞30%` 이상 → 높음. `＞`, `＜`는 전각 기호라서 반각으로 바꾼 뒤 파싱합니다.
### 6-2-1. 데이터 정제 규칙 (BCNB `Patient ID` 기준)

**① Ki-67 판정 규칙**
- **Ki-67은 20%를 기준으로 높음(≥ 20%) / 낮음(< 20%)을 측정한다.**
- **Ki-67이 20%보다 작은데 Luminal B로 판단된 데이터는 intermediate(중간)로 판단하거나 데이터를 사용하지 않는다.**
  - 대상 14명 (Ki-67 15% 10명, 18% 4명): **278, 455, 460, 481, 516, 526, 542, 545, 620, 645, 653, 795, 821, 891**
  - 함께 볼 경계 사례: Ki-67이 범위 문자열 `15-20%`인 Luminal B 6명 (**157, 314, 385, 532, 632, 647**)도 20% 미만인지 알 수 없어 같은 방식으로 처리합니다.

**② ER · PR과 아형이 맞지 않는 데이터 → 사용하지 않는 것을 추천**
| 문제 | 왜 잘못됐나 | Patient ID | 인원 |
|---|---|---|---|
| ER− / PR− / HER2−인데 **Luminal A** | 호르몬 수용체가 모두 음성이면 Luminal이 될 수 없음 (삼중음성이어야 함) | **49, 162, 420, 449, 623** | 5 |
| ER− / PR+ / HER2−인데 **Luminal A** | ER 음성 · PR 양성은 드물고 검사 오류일 가능성이 높으며, Luminal A의 조건(ER 양성)에도 맞지 않음 | **953** | 1 |
| ER− / PR+ / HER2−인데 **Luminal B** | 위와 같음 (ER 음성 · PR 양성 조합) | **199, 619, 842, 844** | 4 |

**검토 후 사용하기로 한 데이터 (제외하지 않음)**
| 문제 | Patient ID | 인원 | 처리 |
|---|---|---|---|
| ER+ / **PR−** / HER2−인데 **Luminal A** | **209, 242, 381, 489, 546, 573, 642, 832, 1024** | 9 | St. Gallen 2013 기준과는 다르지만 사용. ER · PR 라벨을 그대로 씀 |

**③ 그 밖에 확인이 필요한 데이터**
| 문제 | Patient ID | 처리 |
|---|---|---|
| Ki-67 80%인데 Luminal A (ER+ / PR+ / HER2−) | **174** | Ki-67 또는 아형 표기 오류로 보임 → 사용하지 않는 것을 추천 |
| HER2 양성인데 Luminal B (다른 ER+ / HER2+ 환자 155명은 `HER2(+)`로 표기됨) | **279, 484, 594, 1054** | St. Gallen 기준으로는 "Luminal B (HER2+)"로 가능하지만 BCNB 안에서 표기가 일관되지 않음 → 분자 아형 평가에서만 제외 |

**적용 범위**
- ②의 제외 대상 10명과 ③의 174번은 **ER · PR 예측과 분자 아형 평가에서 제외**합니다. 이 환자들의 HER2 · Ki-67 · 림프절 라벨은 그 자체로는 모순이 없어서, 모듈 2와 모듈 3의 HER2 · Ki-67 학습에는 그대로 써도 됩니다.
- 분자 아형 정답은 BCNB `Molecular subtype` 열을 그대로 쓰지 않고, **ER · PR · HER2 · Ki-67(20%) 값으로 정한 규칙에 따라 다시 계산**합니다.
- 제외한 환자 목록은 코드(`exclude_ids` 등)로 관리하고, 제외 사유를 README에 적습니다. BCNB 약관상 환자별 라벨은 공개하지 않으므로, **Patient ID 목록과 사유만** 기록합니다.

**그 밖의 주의점**
- **HER2 4단계 중 2+가 가장 어렵습니다.** H&E만으로는 2+ 안의 양성·음성 구분이 특히 어렵다고 알려져 있습니다.
- 모듈 2와 같은 BCNB 공식 분할(6 : 2 : 2)을 써서, 통합 리포트에서 같은 테스트 환자의 결과를 함께 보여줍니다.

### 6-3. 평가 설계
| 마커 | 비교하는 기존 검사 값 | 일치도 지표 |
|---|---|---|
| ER, PR | BCNB 판독 (양성 / 음성) | AUC, 민감도·특이도, Cohen κ (+ TCGA 외부 검증 AUC) |
| HER2 | BCNB 판독 (양성 / 음성, 0 / 1+ / 2+ / 3+) | 양성/음성: AUC, κ / 4단계: **가중 κ (quadratic)**, 혼동행렬 |
| Ki-67 | BCNB 판독 (% 값) | 20% 기준: AUC, 민감도·특이도, Cohen κ / %: MAE, ICC, Bland-Altman (숫자 값 1,003명) |
| 분자 아형 | BCNB `Molecular subtype` | 4분류 정확도, Cohen κ |

**화면:** "AI 예측 vs 기존 검사 결과"를 나란히 보여주고 **일치 / 경계 / 불일치** 배지를 붙입니다. 불일치 케이스만 모아 보는 화면을 둡니다.

### 6-4. 기존 모델 / 기대 성능
- H&E → ER: AUC 약 0.85–0.92 / PR: 약 0.80 / HER2 양성·음성: 약 0.75–0.85 (HER2 2+ 구간은 약 0.62로 어려움).

- Ki-67(H&E): 연속값 예측은 어려운 편이라 **20% 기준 이진 분류**가 현실적입니다.

## 7. 모듈 4-B — 멀티모달 유사 환자 검색

**범위**
- H&E 슬라이드 벡터와 임상 정보를 합친 **환자 벡터**로 비슷한 과거 환자를 찾고, 그 환자들의 **치료와 경과**를 보여줍니다.
- 새 예측값을 만드는 모듈이 아니라 **근거 사례를 제시하는 CDSS 모듈**입니다. 모듈 1–3의 예측을 보완하는 "참고 자료" 역할입니다.

### 7-1. 파트 선택 (택 1)
| | 파트 1. 회의용 유사 사례 | 파트 2. 수술 후 치료 참고 |
|---|---|---|
| 쓰는 시점 | 수술 전 다학제 회의 | 수술 후 병리 → 보조 항암 결정 → 보조 요법 기간 |
| 질문 슬라이드 → 검색 DB | 생검 H&E → **BCNB** | 절제 H&E → **TCGA-BRCA** |
| 보여주는 결과 | 림프절 결과·수술 방법 | 치료·재발·생존 |
| D의 feature 추출 | BCNB 1,058장 | TCGA 300–500장 |

- 두 파트는 목적(수술 계획 / 수술 후 치료)과 DB가 달라 **하나만 골라 진행**합니다. 선택은 1주차 첫 회의에서 하고, D의 feature 추출 대상이 이 선택으로 정해집니다. 두 파트의 자세한 비교는 2-6에 있습니다.
- 7-2부터의 데이터·DB·설계·평가는 **파트 2 기준**으로 썼습니다. 파트 1을 고르면 7-5의 표대로 바꿉니다.
- TCGA는 절제 슬라이드, BCNB는 생검 슬라이드라서 어느 파트를 고르든 두 DB를 섞어 검색하지 않습니다.

### 7-2. 데이터 (현재 파일로 확인)
| 출처 | 환자 수 | 들어가는 정보 | 용도 |
|---|---|---|---|
| **TCGA-BRCA** | 슬라이드가 있는 환자 **1,062명** (슬라이드 1,133장, 전체 약 1.16TB) | 생존 1,048명 (`cbio_OS_MONTHS`, `cbio_OS_STATUS`), 치료 기록 761명 (`drug_names`, `drug_therapy_types`), PAM50 950명 (`cbio_SUBTYPE`), 병기 (`cbio_PATH_T/N/M_STAGE`), 재발 (`cbio_NEW_TUMOR_EVENT_AFTER_INITIAL_TREATMENT`), ER/PR/HER2 상태 | **파트 2 검색 DB** (공개 가능) |
| **BCNB** | 1,058명 | 바이오마커, 림프절 결과, 종양 크기, 나이, 수술 방법 (치료·경과 없음) | **파트 1 검색 DB** (약관상 공개 불가, 로컬 시연) |

- TCGA 슬라이드 목록은 `team_project_mini/data/metadata/slides_files.csv`에 있고, 임상 병합 파일(`tcga_brca_merged.csv`)과 환자 ID로 1,062명이 모두 연결됩니다.
- 슬라이드 전체(1.16TB)는 받기 어려우므로 **모듈 1과 같은 300–500명으로 시작**합니다. 슬라이드 벡터는 직접 만든 `wsi_pipeline`으로 뽑습니다.
- 선행항암을 받은 환자의 절제 조직은 TCGA 학습 데이터(치료 전 조직)와 달라서 파트 2의 검색 대상에서 뺍니다.

### 7-3. 환자 DB와 설계 (파트 2 기준)

**환자 DB 구성 (환자 1명 = 1행)**
| 구분 | 내용 | 용도 |
|---|---|---|
| ① 검색용 벡터 | 슬라이드 벡터 + 임상 정보를 융합한 환자 벡터 (예: 128차원) | 비슷한 환자 찾기 |
| ② 비교용 정보 | 나이, 종양 크기, ER/PR/HER2, (BCNB) Ki-67, 병기, 아형 | "어디가 비슷한지" 표시 |
| ③ 결과 정보 | 받은 치료, 림프절 결과, 재발·생존 경과, 슬라이드 썸네일 | 의사가 참고하는 부분 |

```json
{
  "case_id": "TCGA-A7-A0DC", "source": "TCGA",
  "embedding": [0.12, -0.83, "..."],
  "age": 63, "ER": "Positive", "PR": "Positive", "HER2": "Negative",
  "stage": "Stage IIA", "pN": "N1a", "pam50": "LumA",
  "treatment": ["cyclophosphamide", "doxorubicin", "tamoxifen"],
  "recurrence": "No", "os_months": 133.0, "os_status": "LIVING",
  "thumbnail": "thumbs/TCGA-A7-A0DC.png"
}
```
(값은 형식 예시입니다.)

**설계**
```
[입력] 슬라이드 벡터 (직접 만든 wsi_pipeline + ABMIL) ─────────┐
       임상 정보 (나이, 종양 크기, ER/PR/HER2, 병기 등) ─ MLP ─────┤
                                                                 ▼
                     융합 네트워크 → 환자 벡터 (128차원, L2 정규화)
                     학습: metric learning (triplet loss)
                       "같은 아형 · 같은 림프절 상태 · 같은 재발 여부"면 가깝게
                                                                 ▼
                     FAISS 인덱스 (학습 환자만 넣음) → 가까운 환자 k명 검색
                                                                 ▼
[출력] 비슷한 환자 k명의 카드 + 이웃 환자의 재발 비율 + 비슷한 이유(공통 특징)
```

**작업 흐름 (스크립트)**
| 스크립트 | 하는 일 |
|---|---|
| `build_case_db.py` | 임상 파일 정리(필요한 열, 결측 처리, 치료 이름 정규화) → 슬라이드 벡터 불러오기 → 환자 벡터 계산 → FAISS 인덱스와 메타데이터(Parquet) 저장 |
| `train_fusion.py` | 융합 네트워크를 metric learning으로 학습 |
| `search_case.py` | 질문 환자의 벡터로 k명 검색 → 메타데이터를 붙여 반환 (UI · 통합 리포트용 JSON) |
| `evaluate_retrieval.py` | 아래 평가 지표 계산 |

### 7-4. 평가 (파트 2 기준)
| 지표 | 의미 |
|---|---|
| precision@k (아형 · 림프절 상태) | 검색된 k명 중 질문 환자와 같은 아형 · 같은 림프절 상태인 비율 |
| 이웃 기반 재발 예측 (AUC, C-index) | 이웃 환자의 재발 비율로 질문 환자의 실제 재발을 얼마나 맞히는가 |
| **사진만 / 임상만 / 융합 비교** | 같은 지표를 세 방식으로 계산해 **멀티모달 효과**를 보여줌 |
| 치료 일치율 (참고) | 이웃 환자가 받은 치료 계열(항암 / 호르몬 / HER2 표적)이 질문 환자와 같은 비율 |

- **누수 방지:** 검색 DB에는 **학습 환자만** 넣고, 질문 환자(테스트)는 넣지 않습니다. 자기 자신이나 학습에 쓴 환자가 검색되면 성능이 부풀려집니다.
- 분할은 모듈 1과 같은 TCGA 분할(환자 단위, 수집 기관 TSS 코드 기준)을 씁니다.

- 위 연구 정보는 제 기억에 의한 인용이라, 발표 자료에 쓰기 전 원문으로 확인이 필요합니다.

**한계**
- (파트 2) TCGA 치료 기록은 2000년대 미국 진료 기준이라 지금 지침과 다를 수 있습니다. 화면에 "과거 사례이며 현재 권고가 아님"을 표시합니다.
- (파트 2) 재발 이벤트가 적어(재발 기록 885명 중 100명) 이웃 기반 재발 예측은 흔들릴 수 있습니다.
- (파트 1) BCNB는 공개할 수 없어 시연이 로컬 환경으로 한정되고, 치료·경과를 보여줄 수 없습니다.

**실현성:** ★★★★☆ (고른 파트의 슬라이드 feature 추출에 GPU 시간이 따로 필요)

## 9. 팀 배정 및 6주 일정 (4명)

### 9-1. 인원 배정
| 담당 | 맡을 일 | 작업량 |
|---|---|---|
| **A** | `wsi_pipeline` + **BCNB feature 추출** + **모듈 2 (림프절 전이)** | ●●●●○ |
| **B** | `wsi_pipeline` + **BCNB feature 추출** + **모듈 3 (바이오마커)**: ER · HER2 → PR → Ki-67 단계식 + 일치도 평가 + 일치 / 경계 / 불일치 화면 | ●●●●○ |
| **C** | `wsi_pipeline` + **TCGA feature 추출** + **모듈 1 (재발 위험)**: TCGA HR+ 300–500장 | ●●●●○ |
| **D** | `wsi_pipeline` + **TCGA 또는 BCNB feature 추출 (파트 선택에 따라)** + **모듈 4-B (멀티모달 유사 환자 검색, 파트 1 · 2 중 택 1)** + **통합 UI** + **LLM 통합 리포트** | ●●●●○ |

- **`wsi_pipeline`은 조원마다 각자 독립적으로 만듭니다.** 단계 구성(2-2)은 같지만 코드와 feature는 각자 만들어 각자 씁니다.
- A와 B는 둘 다 BCNB를, C와 D는 둘 다 TCGA를 쓰지만 feature는 각자 뽑습니다. A · B는 외부 검증용 TCGA feature도 직접 뽑습니다.
- 원본 WSI는 9-4의 공용 저장소에 한 번만 내려받아 두고 같이 읽습니다.
- D는 직접 뽑은 슬라이드 벡터로 딥러닝 융합 모델과 검색을 만들고, 모듈 1·2·3 결과를 묶는 화면과 리포트도 맡습니다.
- **모듈 4-B는 1주차 첫 회의에서 파트 1(회의용 유사 사례, BCNB)과 파트 2(수술 후 치료 참고, TCGA) 중 하나를 고릅니다.** D가 어떤 데이터의 feature를 뽑을지가 이 선택으로 정해집니다.
- 네 명이 각자 feature를 추출하므로, **1주차 첫 회의에서 GPU 사용 순서를 정합니다.**

### 9-2. 6주 일정
| 주차 | A (파이프라인 + 모듈 2) | B (파이프라인 + 모듈 3) | C (파이프라인 + 모듈 1) | D (파이프라인 + 모듈 4-B + UI + 리포트) |
|---|---|---|---|---|
| **1주** | BCNB 다운로드, 파이프라인 뼈대(조직 분할, 타일링) | 파이프라인 뼈대, BCNB 라벨 정리 (Ki-67 범위 문자열 변환), TCGA ER/PR 상태 열 정리 | 파이프라인 뼈대, TCGA HR+ 슬라이드 목록 작성, 다운로드 시작 | **4-B 파트 선택**, 파이프라인 뼈대, TCGA 환자 DB 스키마 설계, 임상 · 치료 · 경과 열 정리 (치료 이름 정규화), **결과 JSON 형식을 팀과 합의** |
| **2주** | **BCNB feature 추출** | **BCNB feature 추출**, 평가 지표 코드(κ, 가중 κ, ICC, Bland-Altman) | 유사 RS 계산(21-gene 공식), TCGA feature 추출 | **TCGA feature 추출**, 임상 정보만으로 kNN 검색 베이스라인, 평가 코드(precision@k, 이웃 기반 재발 AUC), UI 뼈대 |
| **3주** | DL-CNB 재현 (베이스라인) | **ER, HER2 모델** 1차 | RS 회귀 모델 1차 | TCGA 슬라이드 벡터로 융합 네트워크 + metric learning 1차 |
| **3주 말** | **중간 점검: 범위 조정 여부 결정** (9-3 참고) | | | |
| **4주** | encoder 비교, 임상변수 fusion, calibration | PR, Ki-67 모델, HER2 4단계 | 고위험 분류, Cox 재발 모델 | FAISS DB 구축, **사진만 / 임상만 / 융합 비교**, 통합 리포트 프롬프트 설계 |
| **5주** | TCGA feature 추출 → 외부 검증, 히트맵 | 일치 / 경계 / 불일치 배지, 불일치 모아보기, TCGA feature 추출 → 외부 검증 | 히트맵, 결과를 UI에 연결 | 환자 카드 화면 연결, 모듈 1·2·3 결과 연결, 통합 리포트 완성 |
| **6주** | **수요일까지 기능 동결** → 버그 수정, README · 라이선스 정리, 발표 자료, 시연 리허설 | | | |

D 칸은 **4-B 파트 2(TCGA)** 기준입니다. **파트 1을 고르면** 1–3주의 TCGA 작업을 BCNB로 바꿉니다: 1주 BCNB 환자 DB 스키마(림프절 결과 · 수술 방법) 정리, 2주 BCNB feature 추출과 이웃 기반 림프절 전이 AUC 평가 코드, 3주 BCNB 슬라이드 벡터로 융합 네트워크 1차. 4–5주는 같습니다.

### 9-3. 3주 말 중간 점검 기준
| 상황 | 줄일 범위 |
|---|---|
| 모듈 1이 늦어짐 | 생존분석(Cox)은 빼고 **RS 예측 + 고위험 분류**까지만 |
| 모듈 2가 늦어짐 | **N0 vs N+ 이진 분류**만 완성하고 3구간 · 임상 fusion은 "향후 과제"로 |
| 모듈 3이 늦어짐 | **ER, HER2(양성 / 음성)만 완성**하고 PR, Ki-67, HER2 4단계, 분자 아형은 "향후 과제"로 |
| D가 과부하 | 통합 리포트를 고정 템플릿 + LLM 요약 한 단락으로 축소 |
| (4-B) 슬라이드 벡터 추출이 늦어짐 | 융합 모델 대신 **임상 정보 kNN + 슬라이드 벡터 단순 이어붙이기**로 검색하고, metric learning은 "향후 과제"로 |

### 9-4. 미리 확인할 위험 요소
1. **GPU:** WSI 1,000장 안팎의 feature 추출은 GPU 1장 기준으로 하루에서 며칠 걸릴 수 있습니다(환경에 따라 다름). 조원마다 각자 feature를 뽑으므로 **GPU 사용 순서를 미리 정해 두는 것**이 일정의 핵심입니다.
2. **저장공간:** WSI는 장당 수백 MB에서 수 GB입니다. BCNB + TCGA 500장이면 수백 GB 이상 필요할 수 있으니 공용 저장소를 정해 두세요.
3. **결과 형식 통일:** 1주차에 "모듈 → UI"로 넘기는 JSON 형식을 정해야 5주차 통합이 순조롭습니다.
